# Signed Shopify APP_UNINSTALLED webhook boundary (No Deploy)

`acceptWorkerShopifyUninstallWebhook` is a Worker-compatible Web Fetch security boundary for future use. **No Shopify route or deployment imports this module yet.** It requires a correctly configured Staging/Production Worker identity, HTTPS URL matching the configured Shopify origin, POST method and the exact `/webhooks/app/uninstalled` path, valid Shopify webhook metadata, and a **64 KiB limit enforced on the streamed body**, then validates the synthetic-HMAC-compatible Shopify Base64 SHA-256 signature using `crypto.subtle.verify` *before* initializing the request-scoped SDK/database connection.

After that, the **real pinned Shopify SDK** `authenticate.webhook` independently validates the raw payload signature and Shopify headers and provides the trusted uninstall event. Only then is a caller-supplied `onVerified` callback invoked; this module **does not delete merchant data itself**. It always closes request-scoped SDK/Prisma context, even if the callback fails. Tampered/unsigned/unsupported/wrong-tier/oversized requests must never open a database.

GitHub CI generates a separate Cloud Prisma Client, runs the actual Shopify React Router SDK with synthetic credentials and signed webhook payloads, and reruns Shopify SDK/session/Web Streams and patched GraphQL tooling checks. It makes no Shopify API calls, has no real customer payloads, does not touch Neon/Cloudflare and cannot submit/publish an app. Full Cloudflare Worker bundling, real Shopify webhook delivery, replay-id persistence, authenticated admin JWT/OAuth acceptance and Neon staging readiness remain blockers. Importantly **this does not clear the unpatched `braces` development dependency audit**.
